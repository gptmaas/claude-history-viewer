# CodeMemory v0.7.3 — 方案生成与技术评审

## Context

v0.7.2 已经让流水线可手动记录和流转。v0.7.3 开始接入 AI 生成和评审，但边界仍然保守：AI 负责生成需求、产品方案、技术方案、任务拆分和评审报告，是否通过由用户确认。

该版本不自动修改代码，不执行发布动作。

## 目标

- 从一句想法或历史会话生成结构化需求草案。
- 生成产品方案、验收清单和产品评审报告。
- 扫描代码库上下文，生成技术方案、任务拆分和测试计划。
- 引入风险分级和门禁结论。

## 分阶段交付

- **Phase 7.3A: 需求生成与澄清** — 需求补全、验收标准、歧义问题。
- **Phase 7.3B: 产品方案与评审** — 用户流程、页面变化、状态覆盖、产品风险。
- **Phase 7.3C: 技术方案与任务拆分** — repo scanner、影响面、测试计划、技术评审。

## Phase 7.3A: 需求生成与澄清

### 输入来源

- 用户手动输入一句想法。
- 选中历史会话片段。
- 粘贴错误日志、TODO 或 issue 文本。

### 输出产物

- 需求标题。
- 背景。
- 用户目标。
- 使用场景。
- 范围边界。
- 非目标。
- 初始验收标准。
- 风险和未知问题。
- 澄清问题。

### 门禁

进入产品方案阶段前需满足：

- 需求目标明确。
- 至少一个可验证验收标准。
- 范围边界不为空。
- P0 阻塞问题为 0，或用户明确允许带风险推进。

## Phase 7.3B: 产品方案与评审

### 输出产物

- 用户流程。
- 页面/模块变化。
- 信息架构。
- 状态与边界情况。
- 交互规则。
- 验收用例。
- 产品风险。
- 版本范围。

### 产品评审维度

- 是否解决原始需求。
- 是否有明确用户路径。
- 是否覆盖空状态、错误状态、加载状态。
- 是否可验收。
- 是否符合当前产品形态。
- 是否存在不必要复杂度。

### 流转规则

- AI 可生成评审结论。
- 默认进入 `waiting_review`。
- 用户点击通过后才能进入技术方案阶段。

## Phase 7.3C: 技术方案与任务拆分

### Repo scanner

扫描范围应可配置，默认只扫描当前项目目录：

- 文件树摘要。
- 关键配置文件。
- 路由/API 目录。
- 数据模型。
- 组件目录。
- 测试脚本。
- 近期 git diff。

### 输出产物

- 影响文件和模块。
- 数据模型变更。
- API 设计。
- 前端组件设计。
- 本地任务/后台任务设计。
- 测试策略。
- 迁移策略。
- 回滚策略。
- 风险清单。
- 任务拆分。

### 风险分级

- P0：必须人工确认，不允许自动流转。
- P1：默认阻塞，用户可配置放行。
- P2：可自动流转，但进入报告。
- P3：信息提示。

### 验收标准

- 需求可一键生成草案并保存为阶段产物。
- 产品方案和产品评审可生成并记录。
- 技术方案能引用实际 repo 上下文。
- 技术评审能输出风险等级。
- 任务拆分可作为 v0.7.4 Executor 输入。

## 非目标

- 不修改代码。
- 不运行测试。
- 不自动提交 git。
- 不执行构建或发布。
