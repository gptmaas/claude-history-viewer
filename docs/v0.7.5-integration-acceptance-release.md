# CodeMemory v0.7.5 — 集成验收与发布准备

## Context

v0.7.4 已经能自动完成开发任务和单元级验证。v0.7.5 负责把变更推到更接近发布的阶段：集成测试、需求验收、构建、changelog 和 release notes。

本版本仍以“发布准备”为边界。推送远端、创建公开 release、上传安装包或应用商店发布必须人工确认。

## 目标

- 自动启动本地服务并运行集成/E2E 测试。
- 收集截图、日志、测试报告作为验收证据。
- 按需求验收标准生成逐项验收报告。
- 自动生成 changelog、版本号建议、release notes。
- 在发布前执行 build / tauri build，并进入人工发布门禁。

## 分阶段交付

- **Phase 7.5A: 集成测试 runner** — 服务启动、API/E2E、截图和日志收集。
- **Phase 7.5B: 需求验收报告** — 验收标准逐项判断、证据链接、偏离检测。
- **Phase 7.5C: 发布准备** — build、tauri build、changelog、release notes、发布门禁。

## Phase 7.5A: 集成测试 runner

### 测试范围

适合桌面版的关键路径：

- App 启动后 Dashboard 正常渲染。
- 数据源扫描完成。
- 会话列表可打开。
- 搜索可用。
- 流水线项目可创建。
- 阶段状态可流转。
- 本地数据库读写正常。

### 产物

- 集成测试计划。
- 测试环境配置。
- 测试执行结果。
- 失败截图。
- 控制台日志。
- 服务日志。
- 修复记录。

### 验收标准

- 能从流水线阶段启动集成测试。
- 能自动启动和停止本地服务。
- Playwright/E2E 失败时能保存截图。
- 测试结果能关联到对应流水线阶段。

## Phase 7.5B: 需求验收报告

### 报告内容

- 原始需求。
- 验收标准逐项结果。
- 证据链接：会话、diff、截图、测试日志、构建日志。
- 未完成项。
- 需求偏离。
- 风险残留。
- 建议结论：通过 / 不通过 / 需人工确认。

### 自动判断边界

可以自动判断：

- 测试是否通过。
- 页面是否存在关键元素。
- API 是否返回预期状态。
- 构建是否成功。

必须人工确认：

- UI/体验主观判断。
- 文案是否符合预期。
- 涉及真实用户数据。
- 涉及对外发布。

## Phase 7.5C: 发布准备

### 发布产物

- 发布清单。
- 版本号建议。
- changelog。
- build 结果。
- Tauri build 结果。
- release notes。
- 回滚说明。

### 发布门禁

自动进入发布准备前必须满足：

- 需求验收通过或用户确认带风险通过。
- build 通过。
- 工作区无未解释的无关改动。
- 发布命令在白名单内。
- 没有 P0 风险。

### 必须人工确认的动作

- git commit。
- git tag。
- git push。
- 创建 GitHub release。
- 上传安装包。
- 发布到应用商店。
- 执行任何不可逆操作。

### 验收标准

- 能生成验收报告并保存到流水线产物。
- 能生成 changelog 和 release notes 草稿。
- 能运行 build / tauri build 并记录结果。
- 能把发布阶段停在 `waiting_review`，等待用户确认。

## 非目标

- 不默认推送远端仓库。
- 不默认创建公开 release。
- 不实现团队审批流。
- 不实现云端分发系统。
