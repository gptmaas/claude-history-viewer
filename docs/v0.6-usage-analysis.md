# CodeMemory v0.6 — 用量分析（Usage Analysis）

## Context

v0.5 完成协作分享功能后，CodeMemory 已具备完整的数据采集、分析、搜索和分享能力。v0.6 聚焦 **用量分析**，让用户能够按 AI 模型维度追踪 API 请求次数和 Token 消耗趋势，为成本优化提供数据支撑。

当前系统的原始 JSONL 数据中包含 `msg.message.model`（模型名称）和 `msg.message.usage`（含 `input_tokens`、`output_tokens`、`cache_read_input_tokens`），但解析器和数据库均未提取这些字段。本版本将打通完整的数据链路：**解析 → 存储 → 查询 → 展示**。

## 目标

- 从原始数据中提取模型名称和实际 Token 用量
- 按模型维度展示 API 请求次数和 Token 消耗
- 提供每日趋势图表（堆叠面积图 + 堆叠柱状图）
- 在侧边栏添加"用量分析"菜单入口

## 分阶段交付

- **Phase 6A: 数据链路** — 解析器提取 model/usage → Schema 变更 → 存储到 DB → 回填历史数据
- **Phase 6B: 用量分析页** — API 端点 → 图表组件 → 页面 → 菜单入口

### ClaudeCode 解析器变更

**文件**: `lib/parsers/claude-code.ts`

在 `parseSessionData` 方法的 assistant 消息分支（~line 73），从 `msg.message` 提取 model 和 usage：

```typescript
} else if (msg.message?.role === 'assistant') {
  const uuid = msg.uuid || msg.message?.id
  if (!uuid) continue

  const model = msg.message?.model || undefined
  const rawUsage = msg.message?.usage
  let usage: MessageUsage | undefined
  if (rawUsage) {
    usage = {
      inputTokens: rawUsage.input_tokens || 0,
      outputTokens: rawUsage.output_tokens || 0,
      cacheReadInputTokens: rawUsage.cache_read_input_tokens || 0,
    }

  parsed = {
    type: 'assistant',
    role: 'assistant',
    content: msg.message?.content || msg.content,
    uuid,
    sessionId,
    timestamp: msg.timestamp,
    model,
    usage,
  }
}
```

> Codex CLI 解析器无需修改，model/usage 字段将为 undefined。

### DbDataSource — 核心查询

**文件**: `lib/db-data-source.ts`

`getUsageAnalysis(userId, dateRange?)` 方法，三条 SQL 查询：

1. **每日每模型请求计数**：统计 `type = 'assistant'` 的消息数，按 `date_trunc('day', timestamp)` 和 `model` 分组
2. **每日每模型 Token 用量**：从 `usage` jsonb 提取 `inputTokens + outputTokens`，按日和模型分组
3. **模型汇总**：跨日期范围的总请求数和 Token 总量

查询结果 pivot 为 Recharts 友好的动态键格式（date + 每个模型一个字段）。

使用 `COALESCE(model, 'unknown')` 处理无模型信息的历史消息。

## 风险与开放问题

1. **历史数据回填**：`parseVersion` 增至 2 会标记所有原始文件为待重解析。下次 sync 触发时批量处理，可能导致短暂 CPU 峰值。对于立即回填需求，可手动调用 `parseAllPendingRawFiles`。
2. **无 model 的历史数据**：部分历史消息可能不包含 model 字段（早期 Claude Code 版本）。这些消息将归类为 "unknown"，仍计入总用量。
3. **Token 数据准确性**：`usage` 字段来自 API 响应，是实际消耗而非估算。但早期消息可能缺少此字段，此时 Token 统计不完整。
4. **图表颜色冲突**：模型数量超过 10 个时颜色会重复。考虑动态生成颜色或分组展示。

4. 访问 `/usage-analysis`，确认页面加载、图表渲染
5. 检查侧边栏"用量分析"菜单项高亮正常
6. 切换日期范围（7d/30d/90d/全部），确认数据正确刷新
7. 验证无 model 的历史消息归类为 "unknown"
