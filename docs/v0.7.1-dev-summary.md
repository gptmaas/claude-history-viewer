## 交付内容

### Phase 7.1A: SQLite Schema

引入 `better-sqlite3` + Drizzle ORM 作为本地数据库层，替代直接读取 JSONL 文件的方式。

| 文件 | 说明 |
|------|------|
| `lib/local-db/schema.ts` | 7 张表定义（local_sources, local_raw_files, local_sessions, local_messages, local_projects, local_index_runs, schema_version） |
| `lib/local-db/index.ts` | DB 初始化 singleton（WAL 模式，外键约束，懒加载） |
| `lib/local-db/migrate.ts` | 版本化迁移（v1 建表 + FTS5 + 触发器，v2 添加 type/timestamp 索引） |

复用现有 `lib/parsers/` 的 ClaudeCodeParser 和 CodexCliParser，构建扫描 → 解析 → 入库的完整流水线。

| 文件 | 说明 |
|------|------|
| `lib/local-scanner/scanner.ts` | 递归发现 JSONL 文件，mtime/size 增量检测 |

| `lib/local-scanner/source-sync.ts` | 桌面配置数据源同步到 SQLite |
| `lib/local-scanner/auto-scan.ts` | 启动扫描 + 5 分钟定时扫描 |

## 技术决策

| 决策 | 选择 | 原因 |
|------|------|------|
| SQLite 库 | better-sqlite3 | 同步 API，零配置，Tauri 兼容 |
| ORM | Drizzle ORM (sqlite-table) | 与 PostgreSQL 层保持一致 |
| 全文搜索 | FTS5 虚拟表 + 触发器自动同步 | SQLite 原生支持，无需外部依赖 |
| 代码位置 | `lib/local-db/` 而非 `packages/local-engine/` | 紧耦合 Next.js，避免 monorepo 复杂度 |
| 时间存储 | integer（Unix 毫秒时间戳） | SQLite 无原生 timestamp 类型，整数高效 |
| JSON 存储 | text 列 + Drizzle `mode: 'json'` | SQLite 无 jsonb，用 text + 自动序列化 |
| 索引策略 | v2 迁移添加 type/timestamp 索引 | COUNT WHERE type= 扫全表 → 加索引后提升 786x |

## 遗留问题

### P1: 需要修复

1. **Dashboard stats 查询偏慢（~1s）**：`getDashboardStats()` 执行 9 条串行 SQL 查询。可以合并为 1-2 条聚合 SQL，或引入本地内存缓存层。
2. **Session detail 大会话加载慢（1.6s / 323 消息）**：assistant 消息 content 通常很大（含工具调用结果）。需要分页加载消息或按需加载 content。
3. **FTS5 触发器在 bulk insert 时性能问题**：每条 INSERT 触发一次 FTS5 更新。大量入库时应临时禁用触发器，批量完成后再重建 FTS5。

### P2: 功能待完善

4. **Analytics 统计不完整**：`getAnalyticsStats()` 中 weeklyActivity、toolUsageStats、toolUsageTrend、sessionDurationStats、projectActivityHeatmap、estimatedTokenUsage 均返回空/默认值。需要在 SQLite 中实现完整聚合。
5. **增量扫描未验证删除场景**：当源文件被删除时，scanner 检测到 deletedFileIds 但 indexer 只删除了 local_raw_files 记录，未级联删除关联的 sessions/messages。
6. **local_projects 表未使用**：schema 定义了 local_projects 但 indexer 未写入。getProjects() 直接从 local_sessions 聚合查询，应改用 local_projects 提升性能。
7. **首次启动体验**：Tauri 启动后等待 health → 触发初始化 → 全量扫描。907 会话的全量扫描约 60s，期间用户看到空数据。应有进度提示。

### P3: 后续优化

8. **Drizzle ORM 初始化开销**：首次调用 `getDb()` 有 ~500ms 的 ORM 初始化开销。生产模式下影响较小，但 dev 模式下每次热重载都会触发。
9. **Schema 迁移未使用 Drizzle Kit**：手动管理迁移 SQL。后续应切换到 `drizzle-kit generate` + `drizzle-kit migrate` 标准流程。
10. **搜索结果高亮**：FTS5 支持 `snippet()` 和 `highlight()` 函数，当前未使用，搜索结果只有纯文本 snippet。
11. **`packages/local-engine/` 未清理**：该目录仍含 placeholder README，v0.7.1 的代码实际放在 `lib/local-db/` 和 `lib/local-scanner/` 下，应删除空包或更新 README。
12. **`DATA_SOURCE_MODE=local` 回归未验证**：本地模式（非桌面）仍使用 LocalDataSource 直接读文件。需要确认环境变量切换后不会因 better-sqlite3 模块加载而报错。
